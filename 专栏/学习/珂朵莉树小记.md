## 珂朵莉树简介



珂朵莉树是珂朵莉发明的一种暴力数据结构，常用于解决区间颜色段覆盖问题，在随机数据下有不俗的表现，与线段树 $O(n \log n)$ 的时间复杂度相比，随机数据下珂朵莉树 $O(n \log \log n)$ 的时间复杂度更优，同时，珂朵莉树还可以解决许多线段树解决不了的问题。



## 图解珂朵莉树



珂朵莉树本质是比较暴力的。



珂朵莉树将每个颜色段以 $(l,r,x)$ 的方式存储，意思是区间 $[l,r]$ 只有一种颜色 $x$ 。



每次区间颜色段覆盖将 $[l,r]$ 都染成 $x$ 时，我们将 $l$ 和 $r$ 所在的颜色段分裂开，再将夹在 $l$ 所在颜色段到 $r$ 所在颜色段间的所有颜色段删除，插入颜色段 $(l,r,x)$ 。



![](https://cdn.luogu.com.cn/upload/image_hosting/1ydvhlnj.png)



这就是珂朵莉树实现颜色段覆盖的原理。



## 其他操作



值得注意的是，在随机数据下，这样的时间复杂度十分低（原因下文再讲），期望颜色段只有 $O(\log n)$ 个。



删除中间所有颜色段的过程相当于将其遍历了一遍，所以各种奇奇怪怪的操作只要是与颜色段个数线性相关的，期望时间复杂度和区间推平操作一样都是 $O(\log \log n)$ 的（因为使用 set 维护颜色段多了一个 $\log$ ），举几个例子。



1. 将区间倒序，只需把所有颜色段删除后倒叙，修改其 $(l,r)$ 后插入，与颜色段个数线性相关。

2. 求区间贡献，其中 $x$ 的贡献是 $val(x)$ ，那么每个颜色段贡献为 $(r-l+1)val(x)$ 。比如求区间和，或是 $k$ 次方和，只需遍历每个颜色段加上贡献 $(r-l+1)x^k$ 使用快速幂，时间复杂度 $O(\log\log n \log k)$ 。

3. 区间交换，区间复制...

```cpp
struct odt {

    int l, r; mutable int x;

    // mutable 关键字可以让我们直接修改 set 中的 odt 的 x 。

    friend bool operator < (odt a, odt b) {

        return a.l < b.l;

        // 按顺序排序区间

    }

}; set <odt> s;

auto split(int pos) {

    auto it = s.lower_bound({pos, 0, 0});

    if (it != s.end() && it -> l == pos) return it;

    if ((--it) -> r < pos) return s.end();

    int l = it -> l, r = it -> r, v = it -> x;

    s.erase(it); s.insert({l, pos - 1, v});

    return s.insert({pos, r, v}).first;

}

/*

会将下标 pos 所在颜色段 (l,r,x) 分为

(l,pos-1,x) 和 (pos+1,r,x) 两个颜色段，

并返回 (pos+1,r,x) 在 set 中的位置（迭代器）。

*/

inline void assgin(int l, int r, int x) {

    auto R = split(r + 1), L = split(l);

    s.erase(L, R); s.insert({l, r, x});

    // 删除了 set 中 [L, R) 的颜色段
```

## 时间复杂度实践证明



### 实测



时间复杂度不会严谨证明，怎么办？



实践是检验真理的唯一标准。



实测当 $n = 10$ 时，均摊每次询问 $2.67$ 个颜色段。



当 $n = 100$ 时，均摊每次询问 $4.71$ 个颜色段。



当 $n = 1000$ 时，均摊每次询问 $6.53$ 个颜色段。



当 $n = 10000$ 时，均摊每次询问 $7.54$ 个颜色段。



当 $n = 100000$ 时，均摊每次询问 $7.16$ 个颜色段。



当 $n = 1000000$ 时，均摊每次询问 $9.03$ 个颜色段。



当 $n = 10000000$ 时，均摊每次询问 $9.35$ 个颜色段。



以上数据中，当 $n \le 10^4$ 后的数据是通过多次测试取最大值的，大多情况下数据集中在 $6$ 个颜色段。



容易发现，显然随机数据下均摊颜色段数量是 $\log n$ 级别的，甚至比 $\log n$ 还要小很多，测试代码：



```cpp

#include <bits/stdc++.h>

using namespace std;

using ll = long long;

const int maxn = 1e7 + 5;

ll n, q, op, l, r, x, a[maxn];

struct odt {

    ll l, r; mutable ll x;

    friend bool operator < (const odt& a, const odt& b) {

        return a.l < b.l;

    }

}; set <odt> s;

auto split(ll pos) {

    auto it = s.lower_bound({pos, 0, 0});

    if (it != s.end() && it -> l == pos) return it;

    if ((--it) -> r < pos) return s.end();

    ll l = it -> l, r = it -> r, v = it -> x;

    s.erase(it); s.insert({l, pos - 1, v});

    return s.insert({pos, r, v}).first;

}

inline void assgin(ll l, ll r, ll x) {

    auto R = split(r + 1), L = split(l);

    s.erase(L, R); s.insert({l, r, x});

    return;

}

ll query(ll l, ll r) {

    auto R = split(r + 1), L = split(l);

    ll res = 0; for (; L != R; L++) res++;

    return res;

}

mt19937 rng(time(0));

int main() {

    ios::sync_with_stdio(0);

    cin.tie(0); cout.tie(0);

    ll cnt = 0, sum = 0;

    n = q = /*num*/;

    for (int i = 1; i <= n; i++) {

    	a[i] = rng();

    	s.insert({i, i, a[i]});

	}

	while (q--) {

		op = rng() & 1, l = rng() % n + 1, r = rng() % n + 1, x = rng();

		if (l > r) swap(l, r);

		if (op == 1) assgin(l, r, x);

		else cnt++, sum += query(l, r);

	}

	cout << fixed << setprecision(5) << sum * 1.0 / cnt << '\n';

    return 0; 

}
```

### 理论



还是将一下理论吧，但是也是感性证明不需要严谨过程，讲讲为什么颜色段是 $\log n$ 的。



对于每次 $split$ 操作会增加一个颜色段；对于每次 $assign$ 会最多增加 $O(1)$ 个颜色段，删除最多 $(n)$ 个颜色段，但事实上经过研究分析只会有 $O(\log n)$ 个颜色段，珂朵莉树时间复杂度保证就在推平操作。



假设每次操作是随机的，那么 $l$ 和 $r$ 均匀分布，一个点 $j$ 成为端点的概率 $p_j$ 满足： 

$$ p_j \approx \left( \frac{(j-1)^2 + (n-j)^2}{n^2} \right)^m $$



对所有点求和：

$$ \frac{1}{n} \sum_{j=1}^n p_j = O\left(\frac{1}{m}\right) $$ 

表示平均一个端点存活概率随操作次数增加而快速下降。



所以总端点数约为 $O(n + m)$，但由于随机覆盖，大部分会被合并掉。



仅少数端点幸存，根据积分估计：

$$ E[t] = O\left(\frac{n}{m} + \log m\right) $$

当 $m = n$ 时，有：

$$ E[t] = O(\log n) $$



ODT 的每次操作时间取决于区间数 $t$，平均操作时间为：

$$ O(\log t) \approx O(\log \log n) $$



所以总体复杂度为均摊 $O(n \log \log n)$。



感性理解吧，或者当结论记就好了。



### 怎么卡掉珂朵莉树



上文提到过，珂朵莉树复杂度正确的核心是区间推平操作，那么我们只要使初始颜色段尽量多，没有推平，每次询问 $[1,n]$ 就可以让时间复杂度退化至 $O(n^2\log n)$ 。



### 分块套珂朵莉树



结合一下分块思想，把序列分为 $\sqrt n$ 个块，每个块内都是一个珂朵莉树，每次推平时，块外暴力推平，整块打一个标记，每次询问的复杂度为 $O(\log \log n +\log \sqrt n)$ ，最坏情况下总时间复杂度为 $O(m  \sqrt n  \log n)$ 。
